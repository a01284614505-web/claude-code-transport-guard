# First-round independent review and implementation plan

Reviewed original commit `3007550` in full: `bin/`, `lib/`, `prompts/`, `install.sh`, all three test files, `README.md`, and `SECURITY.md`. Findings below cite original lines, not revised lines. Baseline `tests/test-install.sh` and `tests/test-settings.py` passed on Linux; `tests/test-gate.sh` failed 17 expected denials because it calls `python` at line 15 and this machine only has `python3`. The test failure was an environment portability defect, not a measured gate failure.

Architecture: the prompt contract and UserPromptSubmit anchor are advisory and redundant by design; neither is independent evidence of origin because the relay can edit API text. The PreToolUse hook is local and independent of the relay, but only covers Bash. The manual probe measures one chosen echo response and cannot exclude selective relay tampering. The guarded, bare, and raw launchers are explicit user choices. The original README correctly rejects cryptographic integrity and full Shell-sandbox claims, but its broad phrase “prompt-injection resistance” lacks real-model evidence.

Implementation order was: (1) reproduce P0/P1 failures with isolated tests, (2) unify Bash decision path and block local errors, (3) preserve config and sanitize logs, (4) record static and simulated-agent results separately, (5) add CI, versioning, and user/research documentation. Code fix commits: `82183ab`, `1dfde3a`. This review is an internal self-audit, not a third-party validation.

Relevant Claude Code [Hooks reference](https://code.claude.com/docs/en/hooks) was read on 2026-10-13. It documents stdin JSON, deny JSON, exit-code-2 behavior, timeout behavior, and v2.1.295 as the minimum for `onFailure: "block"`. [Settings precedence](https://code.claude.com/docs/en/settings) shows user, project, local, and managed scopes; a user settings hook is not an organizational policy boundary.
