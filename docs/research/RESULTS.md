# Results and unresolved work

The static machine-readable record is [offline-results.json](offline-results.json), generated from [tests/cases.json](../../tests/cases.json). Source versions are original `3007550` and fixes `82183ab`, `1dfde3a`, `93e89eb`, `5ce23c5`. Results are limited to the selected 19 static proposals; the sample is neither random nor representative of all Bash usage. The separate [fake-agent record](agent-results.json) has 4/4 expected Hook outcomes and no real model behavior.

G001/G002 (`fdisk`, `parted`) account for the two improved detections. G016-G019 deliberately demonstrate residual misses: dynamic command construction, long `rm` options, nested interpreter behavior, and encoded execution. After v0.2.0, the CCTG-008 to CCTG-012 fixes (unreleased) make G017 a detection; on the same 19 cases the current code misses 3/14 high-risk proposals and blocks 0/5 benign ones. The table and `offline-results.json` remain the v0.2.0 record and were not regenerated. The original fast path avoids Python startup on some commands, while the changed gate starts Python for every Bash proposal. The displayed medians are noisy single-pass wall times in temporary directories, not a stable latency benchmark; no claim of faster runtime is made. Compatibility checks passed on this Linux host: 32 original gate cases, original settings and install lifecycle tests, 22 new Python regressions (including a loopback fake relay and stub timeout), 4 fake-agent cases, a Termux-style path/shebang simulation, Bash syntax, and Python compilation. A real Android Termux run was not available.

The later [real-client record](real-client-results.json) has **4/4** expected outcomes on Claude Code v2.1.299 with a synthetic loopback API: RC001 allowed a harmless Bash command and created a marker; RC002 denied `rm -rf .ssh` and preserved the temporary fixture; RC003 blocked a harmless command when the Hook path was missing; RC004 blocked it after the Hook's one-second timeout. In the last three cases, the next API request carried a Hook-related error tool result. This verifies these specific client-side lifecycle paths on v2.1.299. It does not involve a real model, real relay, Android device, or broad command corpus. The client process exited zero even for blocked tool calls because the synthetic second response completed normally; test success depends on the file effects and tool results, not merely the process exit code.

The project still cannot stop a relay from reading or altering API requests, including credentials already in a request. The prompt contract cannot authenticate source roles. The Bash gate cannot inspect execution inside scripts, shell expansion, network-capable tools, `Write`/`Edit`, MCP tools, or client actions outside Bash. The documented `onFailure: "block"` requires Claude Code v2.1.295+; older versions retain client-side failure/timeout uncertainty. A local same-user process or a fully compromised device can change or bypass the project. False-positive measurement here covers only five benign examples and is too small for a usability guarantee.

Next maintenance priorities: run installation and shebang checks on actual Termux; expand a curated benign corpus from consented, scrubbed workflows; design explicit policies for non-Bash tools only after their input schemas are tested; and consider a small Shell parser only if it reduces proven high-impact misses without hurting latency or false positives. Consider a separately triggered CI job for the real-client test if its binary download cost is acceptable. Keep command strings out of diagnostic logs and report newly confirmed issues privately through the GitHub security advisory channel.
