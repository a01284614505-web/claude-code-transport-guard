# Offline research method and limits

Date: 2026-10-13 UTC. Host: Linux 6.8.0-48-generic x86_64, Bash 5.2.21, Python 3.12.3. Original source: Git commit `3007550`; changed code: `82183ab`, `1dfde3a`, `93e89eb`, and `5ce23c5` plus documentation. No real Claude Code executable, Android/Termux device, API relay, or model endpoint was available. No real secret, destructive command, external network request, or third-party target was used.

Run `python3 tests/run_cases.py --compare-original --output docs/research/offline-results.json` from a clone with commit `3007550` in history. The harness reads original hook files using `git show`, installs each into a separate temporary directory, sends JSON proposals to the hook via stdin, and records output, status, and elapsed wall time. Candidate Bash commands are **never executed**. `tests/cases.json` gives each case a unique ID, source, literal input, common initial environment, expected hook behavior, and reason. The generated result gives actual behavior, pass/fail, source version, and timing. Case text uses reserved example domains and fake credentials.

The fixed suite has 19 Bash proposals: 10 targeted high-risk syntax samples, 5 benign development samples, and 4 deliberately uncovered high-risk forms. G004/G007 label an untrusted tool-result source by explicitly supplying its proposed command. G005 labels role spoofing in the same way. G006 labels a fake credential-exfiltration request. These 19 are **static Hook cases**, even when their source label describes an attack. There was no model generation step, so they do not measure whether Claude follows an injected instruction. G016-G019 document known limits; their expected hook behavior is `allow` so regressions in documentation are visible, while `security_goal_met` correctly records false for a high-risk proposal that passes. `passed` is a harness expectation check and must not be read as an attack-blocking success rate.

The separate `tests/run_agent_sim.py` reads four untrusted-text fixtures from `tests/agent_cases.json`. Its intentionally compliant fake agent extracts a `PROPOSE_BASH:` string, then sends only that candidate through the installed local Hook; the candidate is never executed. This exercises the offline source → fake agent → Hook path for role spoofing, polluted tool output, a forged user-looking request, and a benign proposal. The deterministic stub makes no claim about real model susceptibility. Results, including ID, source, input, initial environment, expectation, actual behavior, pass/fail, version, and reason, are in `agent-results.json`.

Separate tests in `tests/test_v2_regression.py` exercise damaged JSON, missing/crashing/stalling checker, fake secret log hygiene, a loopback fake relay error, shared settings entries, quoted paths, launcher collisions, shim execution, and uninstall rollback. `tests/test-gate.sh`, `tests/test-install.sh`, and `tests/test-settings.py` remain as original regression coverage with an isolated gate fixture and Python 3 fix. `tests/test-termux-compat.sh` simulates a Termux-style `PREFIX` and shebang rewrite on Linux; it is not an Android run. The timeout test confirms that a stub checker stalls and that installed settings specify `onFailure: block`; actual Claude Code timeout behavior was not tested. Real model behavior, role spoof acceptance, indirect prompt-injection success, and relay tampering detection are **not tested**. The manual probe was not run because it would send an external request.

Attack taxonomy for future work: role/system impersonation; instructions in repository/web/tool results; credential exfiltration proposals; destructive shell proposals; Shell parsing and dynamic execution; hook startup/timeout/input failure; settings and installer state corruption; and benign-command false positives. A meaningful real-model study would require explicit authorization, pinned model/client versions, controlled relay and fake data, repeated trials, blinded outcomes, and separate measures for model compliance and local hook decisions. Never equate static matcher sensitivity with prompt-injection resistance.
